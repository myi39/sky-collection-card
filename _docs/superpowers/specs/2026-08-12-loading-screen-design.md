# ローディング画面（心音）設計書

作成日: 2026-08-12
対象: `sky_collection_card.html`

## 目的

初回表示時に「画像がまだ出てこない」状態を無くす。全カードの表・裏画像を先に取得しきってから本編を見せる。その待ち時間を、既存素材 `movies/心音.mp4` を使ったローディング演出で埋める。

## 素材の実測

`movies/心音.mp4` を ffmpeg で計測した結果。

| 項目 | 値 |
|---|---|
| 尺 | 32.2秒 |
| 解像度 | 1200×674 |
| 映像 | h264 (Main), 30fps, 636kb/s |
| 音声 | AAC-LC, 48kHz, stereo, 317kb/s |
| ファイルサイズ | 3.76MB |
| 内容 | 純黒背景に「SKY AIRRACE / #skyairraceCC」のグレーのロゴが心音のリズムで明滅 |

### 構造

輝度（YAVG）を計測したところ、2部構成であることが判明した。

- **0〜11.5秒**: 暗闇からロゴが徐々に立ち上がる導入部
- **11.5〜32.0秒**: 3.5秒周期の定常ループ。輝度ピークが 12.0 / 15.5 / 19.0 / 22.5 / 26.0 / 29.5秒 と等間隔
- **31〜32.2秒**: 音声がフェードアウト（-59.5dB → -67.1dB）して終息

YUVの黒レベル（Y=16）を基準に実質の明るさへ直すと、導入部は本編の1/10しかない。

| 時刻 | 実質の明るさ (YAVG−16) |
|---|---|
| 0秒 | 0.0 |
| 1.75秒（第1拍） | 1.9 |
| 5.1秒（第2拍） | 2.2 |
| 8.5秒（第3拍） | 4.5 |
| 12.0秒（第4拍） | 10.2 |
| 以降 | 10〜11 で安定 |

**この動画は第4拍（12秒）で本編に入る構成**であり、冒頭3秒はほぼ真っ黒。ローディング画面としては使えない。

CSS `filter: brightness()` で持ち上げる案は、3秒時点を12秒相当にするのに10倍が必要で諧調が破綻するため却下。

### 音声

1秒窓のRMSを計測。心音は1秒目から鳴っており（-30dB）、映像の明滅と同期している。音量は時間とともに増大（-30dB → -23.4dB @29秒）し、31秒以降フェードアウト。

## 決定事項

### 1. 専用のループ動画を新規生成する

元の `movies/心音.mp4` は残したまま、`movies/heartbeat_loop.mp4` を生成する。

```
ffmpeg -ss 10.5 -t 17.5 -i movies/心音.mp4 \
  -vf scale=800:-2 -c:v libx264 -crf 30 -preset slow \
  -profile:v main -pix_fmt yuv420p -movflags +faststart \
  -c:a aac -b:a 96k -ac 1 movies/heartbeat_loop.mp4
```

- 切り出し区間 **10.5〜28.0秒 = 心音ちょうど5拍分**。輝度・音声とも完全に周期的な区間
- ループ継ぎ目を検証済み: 先頭 YAVG 19.2 / 末尾 19.4 でシームレス
- 開始1.5秒で輝度ピーク（YAVG 25.7）に達し、最初の1拍から演出が成立する
- **3.76MB → 268KB（約1/14）**。映像がほぼ黒で圧縮が効くため、サイズの大半は音声

導入部を捨てる理由は上記の通り「実質見えない」ため。動画自体のDLがローディング表示を遅らせる問題（3.76MBだと4Gで約6秒間なにも出せない）も同時に解決する。

`loop` 属性を付けるだけでよく、末尾から先頭へジャンプさせる制御コードは不要。

### 2. 画面構成

全画面オーバーレイ。動画を `mix-blend-mode: screen` で合成する。

動画は 1200×674 の横長だが、背景が純黒・ロゴがグレーのため screen 合成で黒が完全に透過する。スマホ縦画面でもレターボックスが出ず、ページ背景 `#080810` の上にロゴだけが浮く。

```
┌──────────────┐
│              │
│  ⌒SKY AIRRACE⌒  │  ← 動画（screen合成・心音のリズムで明滅）
│  #skyairraceCC   │
│              │
│              │
│ ♪ OFF        │  ← 既存の .bgm-btn（位置そのまま）
└──────────────┘
```

進捗バーは置かない。心音の明滅そのものが待機のsignになる。

### 3. 先読みはキャッシュ充填のみ（メモリ常駐させない）

**「全部ダウンロードする」と「全部メモリに載せる」を分離する。** これを混同すると、過去に発生したモバイルChromeのクラッシュが再発する。

現在の `updateCenterBack()` は、非中央カードの裏画像を `removeAttribute('src')` で完全解放している（中央=フル / 非中央でフリップ中=低画質 / 表向き=解放）。これはGPU/メモリ対策として意図的に入っているもので、**一切変更しない**。

もし全画像を `img.src` に入れて保持すると、裏フル画像だけで 769×1077×4byte × 39枚 ≒ 129MB のデコード済みビットマップが常駐し確実に落ちる。

したがって、**表と裏で扱いを変える**。

**表画像**は元々「全カード常駐デコード」が設計方針なので、既存の `loadAllFronts()` をそのまま使い、**その完了を待つ**。`fetch()` で別途先読みすると二重取得になるため行わない。`loadAllFronts()` は progressive な step 関数なので、完走時にコールバックを呼べるようにする。

**裏画像**は常駐させてはいけないので、`fetch()` で**HTTPキャッシュに入れるだけ**にする。`img.src` には入れない。

- フリップ時に `img.src = ...` した瞬間、キャッシュから即読み込みとなりネットワーク往復がゼロになる
- デコードはフリップアニメ（850ms）の間に間に合う（既存コードのコメントにある通り）

これで「めくったのに画像が出てこない」を解消しつつ、メモリ常駐量は現状から一切増えない。

#### 待機対象

各ディレクトリに39ファイルあるが、HTMLから実際に参照されるのは **37枚**（`players` 36件 + 特殊カード `00_&You1`）。`00_&I表` と `00_&You2` は未参照の残存アセットのため先読み対象に含めない。

| 対象 | 枚数 | サイズ | 方式 |
|---|---|---|---|
| `images/card_front/*.jpg` | 37 | 3.20MB | `loadAllFronts()` の完走を待つ（常駐デコードあり） |
| `images/card_back/*.png` | 37 | 2.55MB | `fetch()` でキャッシュ充填のみ |
| `images/card_back_lo/*.png` | 37 | 1.80MB | `fetch()` でキャッシュ充填のみ |
| **合計** | | **7.55MB** | |

`fetch()` するのは裏の2種＝**74リクエスト / 4.35MB**。パスは `players[]` から導出する（読み込み時に `normalize('NFD')` 済みのため、正規化を自動的に引き継げる）。

#### 先読みの実行条件

- **並列度は6程度に制限する。** 裏画像だけで78リクエストあり、一斉に投げるとブラウザの同時接続数上限で詰まり、表画像の `loadAllFronts()` まで遅延する
- **個別の失敗は無視して続行する。** 1枚が404やネットワークエラーで落ちても、ローディングは明ける。その1枚だけ従来通りフリップ時にネットワーク取得となるだけで、実害は元の挙動に戻るのみ
- **全体タイムアウトを60秒設ける。** 極端に遅い回線で永久に明けない事態を防ぐ。タイムアウト時は未完了のまま本編へ遷移する

#### 先読みしないもの（従来通り遅延）

| 対象 | サイズ | 理由 |
|---|---|---|
| `images/card_front_hi/*.jpg` | 7.55MB | 中央カードの後追いシャープ化用。無くても表示される |
| `images/3d_background/light.jpg` | 4.40MB | 3Dビュー起動時のみ。ローディング明け後に裏で先読みする |
| `3d/*.glb` | 80.5MB | 3Dビュー起動時のみ |

7.95MB の想定待ち時間は WiFiで約3秒 / 4Gで約13秒 / 低速回線で40秒超。4Gでちょうどループ1周（17.5秒）に収まる。

ファイルパスは NFD 正規化が必要（既存の慣習に従う）。

### 4. 明ける条件は自動判定（タップ不要）

**3.0秒以上が経過 かつ 待機対象がすべて完了**した後、**最初に到来する拍の頂点**で自動的に本編へ遷移する。

切り出し版の拍のピークは `currentTime` が **1.5 + 3.5k 秒**（1.5 / 5.0 / 8.5 / 12.0 / 15.5秒）。実測で 0.0s→YAVG 19.2、1.5s→25.7 とピークを確認済み。

したがって**実効的な最短表示時間は5.0秒**になる（3.0秒の条件を満たした直後のピークが5.0秒のため）。当初の想定「3秒ほど固定」よりやや長いが、拍の頂点で明ける演出と両立させるとこの値になる。短くしたい場合は最低待機を撤廃し、1.5秒のピークを許容する形になる。

入場のためのタップは設けない。理由:

- タップに「音を入れる」と「入場する」の2つの役割が乗ると衝突する
- 「DL完了 → ラベル表示 → ユーザーが気づいてタップ」は、DL時間に加えて人間の反応時間が乗るぶん**遅くなる**
- ループ動画には「続き」が存在しないため、居残って見る意味がない

スキップ機能も設けない。画像が揃っていない状態で入ることになり、本設計の目的そのものを壊すため。

### 5. 遷移

先読み完了後、**次の拍の頂点まで待ってから**明ける（最大3.5秒、平均1.7秒）。心音のリズムを断ち切らずに済む。

1. 先読み完了 → 次の拍のピークまで待機
2. 拍の頂点でロゴが `brightness` 上昇 ＋ `opacity` → 0（0.6秒）
3. 同時にカルーセルが `scale(1.04) → 1.0` ＋ `opacity` 0 → 1
4. `♪ ON` の場合のみ、心音をフェードアウトしながらBGMをフェードイン

### 6. 音の扱い — 既存の左下ボタンをそのまま使う

```css
.bgm-btn {
  position: fixed; bottom: 18px; left: 18px; z-index: 200;
  color: rgba(255,255,255,0.28); font-size: 10px;
}
```

`position: fixed` のため、ローディングオーバーレイの上に載せるだけで同じ場所に居続ける。ローディング中だけ `z-index` をオーバーレイより上げる。

**状態を引き継ぐのではなく、最初から最後まで同じ1個のDOM要素**とする。`soundOn` フラグ1つを、ローディング中は動画の音声に、入場後はBGMに向ける。

- 初期状態は **OFF**（autoplay制限により、無音でなければ自動再生できないため強制）
- ラベル: `♪ OFF` → 押すと `♪ ON`
- ON にすると 0.8秒のフェードインで心音が乗る（`max -7.1dB` とそこそこ大きいため、いきなり最大音量にしない）
- 誤タップ対策: 反応するのは左下のピル1箇所のみ。画面のどこを触っても何も起きない（入場は自動のため）
- iOSはサイレントスイッチONで `<video>` の音声が鳴らないため、OSレベルの保護が効く

### 7. BGMの変更

現状の実装には2つの問題がある。

```js
// 最初のユーザー操作から3秒後に再生（autoplay制限の回避）
function onFirstInteraction() { setTimeout(startPlay, 1000); }
document.addEventListener("touchstart", onFirstInteraction, { passive: true });
```

- **画面のどこを触っても1秒後にBGMが鳴る**（コメントは「3秒後」だが実装は1000ms）。音を出したくない人にとって事後のopt-outすらできない
- `<audio ... preload="auto">` により、**BGMの3.97MBがページを開いた瞬間から画像の先読みと帯域を奪い合う**。音をOFFのままの人には完全に無駄

変更内容:

| 項目 | 変更前 | 変更後 |
|---|---|---|
| `preload` | `"auto"` | `"none"` |
| 自動再生 | 初回操作から1秒後に無条件で再生 | 撤去。`♪ ON` を押した人のみ |
| 初期ラベル | `♪ ON`（実態と不一致） | `♪ OFF` |
| 読み込み開始 | ページ表示時 | `♪ ON` を押した時 |

`♪ ON` を押した瞬間に `volume = 0` で `bgm.play()` を呼ぶ。そのユーザー操作でautoplayロックが解除されるため、入場時（ユーザー操作を伴わない）のフェードインが確実に成功する。

音OFFの人は先読み量が 11.9MB → 7.95MB に減り、ローディングも速くなる。

### 新規

- `movies/heartbeat_loop.mp4`（生成物、268KB）
- ローディングオーバーレイの HTML / CSS / JS（`sky_collection_card.html` 内）

### 既存の変更

- `<audio id="bgm">` の `preload` 属性
- BGM制御ブロック（1236〜1271行付近）: 自動再生ロジックの撤去、`soundOn` フラグの導入、初期ラベル修正
