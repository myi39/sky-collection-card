# 音の扉 — 人間による確認チェックリスト

実装は全タスク完了・レビュー済みですが、**画面を見て・耳で聴いて確かめた人はまだ誰もいません。**
サブエージェントにはブラウザがないため、以下はすべて未実行です。

配信は `serve` スキルで。`file://` で開くと `fetch()` がCORSで失敗するので、**必ずHTTPで配信**してください。

## A. PCブラウザ（先にこちらを一周する）

### A-1. 扉が出るか

`sky_collection_card.html` を開く。

- [ ] ページを開いた瞬間に、黒背景の中央に「このサイトでは音が流れます」が出る（心音の映像は見えない）
- [ ] その下に一回り小さく淡い「音のオン／オフは左下でいつでも」がある
- [ ] さらに下に「OK」ボタンがある
- [ ] 左下の音ボタンは見えない（扉の下に隠れている）
- [ ] ページがスクロールしない

コンソール:

```js
const g = document.getElementById('sound-gate');
console.log('gate z-index:', getComputedStyle(g).zIndex);
console.log('gate bg:', getComputedStyle(g).backgroundColor);
console.log('font-family:', getComputedStyle(g).fontFamily.slice(0, 20));
console.log('html overflow:', getComputedStyle(document.documentElement).overflow);
console.log('video paused:', document.getElementById('loading-video').paused);
```

期待:
```
gate z-index: 700
gate bg: rgb(8, 8, 16)
font-family: -apple-system, Blink   ← Papyrus が含まれていないこと
html overflow: hidden
video paused: false                 ← 扉の裏で心音動画が回り、先読みが進んでいる
```

### A-2. OKで扉を抜け、心音が鳴るか

再読み込みしてOKを押す。

- [ ] 扉が 0.4秒でフェードアウトし、心音のロゴが現れる
- [ ] 心音が**フェードインで**鳴り始める（いきなり最大音量にならない）
- [ ] 明滅と鼓動の音が同期している
- [ ] 左下に**波紋の出ているスピーカー**アイコンが現れる
- [ ] ページのスクロールが復活する
- [ ] 数秒後に自動で一覧へ遷移する
- [ ] コンソールに `[loading] revealed at <数値> ms` が1回だけ出る

OKの1〜2秒後にコンソール:

```js
console.log('soundOn:', soundOn);
console.log('video muted:', loadingVideo.muted, '/ volume:', loadingVideo.volume.toFixed(2));
console.log('bgm paused:', bgm.paused, '/ currentTime:', bgm.currentTime.toFixed(2));
console.log('btn aria:', soundBtn.getAttribute('aria-label'), '/ is-muted:', soundBtn.classList.contains('is-muted'));
console.log('svg count:', soundBtn.querySelectorAll('svg').length);
```

期待:
```
soundOn: true
video muted: false / volume: 1.00
bgm paused: true / currentTime: 0.00      ← 解錠のみ。進んでいないこと
btn aria: 音を消す / is-muted: false
svg count: 2                              ← 1 なら textContent でSVGが消えている
```

心音の頭出し（OKを押した**直後**に実行）:

```js
console.log('video currentTime right after OK:', loadingVideo.currentTime.toFixed(2));
```

期待: **1.0 未満**。扉に長く滞在した後でも 0 付近から始まること。

### A-3. ★ 心音 → 静けさ → 蒼穹（今回の本丸のひとつ）

そのまま一覧へ遷移するまで待つ。**耳で確認する。**

- [ ] 一覧が現れると心音が引いていく
- [ ] **心音が完全に消えた後、一拍の静けさがあってから**蒼穹が入る
- [ ] 重なって聞こえる瞬間が**無い**
- [ ] **蒼穹が曲の頭から始まる**（イントロが聞こえる）

遷移から1〜2秒後にコンソール:

```js
console.log('bgm currentTime:', bgm.currentTime.toFixed(2), '/ volume:', bgm.volume.toFixed(2));
console.log('video paused:', loadingVideo.paused, '/ volume:', loadingVideo.volume.toFixed(2));
```

期待:
```
bgm currentTime: 0.xx 〜 1.xx    ← 10 を超えていたら頭出しが効いていない
bgm volume: 0.0x 〜 0.28         ← フェードイン中
video paused: true / volume: 0.00
```

タイミングの計測（OKを押した直後に仕込み、遷移まで待つ）。
**注意: 下の 950〜1150ms という範囲が有効なのはキャッシュが温まっている2回目以降だけです。**
蒼穹の再生開始は mp3 のバッファリング完了を待つため、初回読込では画像111枚と帯域を
取り合って 1150ms を超えます。それは正常な劣化であって失敗ではありません。

```js
let t0 = null;
const iv = setInterval(() => {
  if (loadingDone && t0 === null) t0 = performance.now();
  if (t0 !== null && !bgm.paused && bgm.volume > 0) {
    console.log('bgm started at +', Math.round(performance.now() - t0), 'ms after reveal');
    clearInterval(iv);
  }
}, 20);
```

期待: **950〜1150** の範囲。600以下なら静けさの間が効いていない。

### A-4. ★ 静けさの間にミュートしても音楽が鳴り出さないか

**これはレビューで見つかった不具合の修正確認です。計画の元の手順には無かった項目。**

再読み込み → OK → 一覧が現れ、心音が消えてから音楽が鳴り出すまでの**約1秒の間**に、左下ボタンをタップして音を消す。

- [ ] 音楽が鳴り出さない（1秒後に勝手に鳴り始めたら失敗）
- [ ] もう一度タップして音を出すと、蒼穹が**曲の頭から**鳴る

### A-3b. ★ 初回読込＋低速回線で、遅れて勝手に鳴り出さないか

**最終レビューで見つかった不具合の修正確認。元の手順には無かった項目。**

キャッシュを削除し、Network スロットリングを `Slow 4G` にして再読み込み → OK →
一覧が出た**直後**に左下ボタンをOFFにして、そのまま30秒待つ。

- [ ] 蒼穹が遅れて勝手に鳴り出さない

蒼穹の再生は mp3 のバッファリング完了を待つので、遅い回線ではこの待ち時間が長くなります。
その間にミュートした操作が無視されると、あとから音楽が鳴り出して止められませんでした。

### A-4b. ★ 一覧が現れた瞬間にOFF→ONしても被らないか

再読み込み → OK → **一覧が現れた瞬間（心音がまだ引き終わる前）** に左下ボタンをOFF、
すぐにON。

- [ ] 心音と蒼穹が重なって聞こえる瞬間が無い

### A-5. 2回目以降は頭に戻らないか

### B-2a. ★★ iPhoneでミュートボタンが実際に効くか

**最終レビューで見つかった、一番大事な確認項目です。**

iPhone の Safari は `volume` の指定を無視します（音量は本体で操作するもの、という思想）。
そのため「フェードで音量を0にする」実装は iPhone では**何も起きません**。
今回 `muted` による保険を入れたので、それが効いているかを見ます。

一覧で蒼穹が鳴っている状態にしてから:

- [ ] 左下ボタンをOFFにすると、蒼穹が**実際に聞こえなくなる**（音量が下がるだけでなく止まる）
- [ ] もう一度ONにすると、蒼穹が**また聞こえるようになる**（片道切符になっていない）

**片道になっていたら（OFFにしたきり二度と鳴らない）報告してください。** `muted` を戻す処理が
効いていないことになります。

- [ ] 蒼穹の音量が心音よりはっきり小さい

最後の項目が満たされない（蒼穹が心音と同じくらい大きい）場合、それは `volume` が無視されて
`BGM_VOL = 0.28` が効かず **1.0 で鳴っている**ということです。これはコードでは直せません
（Web Audio を持ち込む必要があり、今回のスコープ外と判断しました）。
気になる音量差なら、次の作業として相談してください。

同じ理由で、**iPhoneでは心音のフェードインも効きません**（OKを押した瞬間に最大音量で入る）。

- [ ] OKを押したときの心音の入り方が、許容できる大きさか

### B-2b. ★ iPhoneで解錠が維持されるか

**A-6 と同じ手順を iPhone で行います。** 設計書が「このプロジェクトはiOSで想定外の挙動を
繰り返し踏んでいる」と書いている当の部分で、PCで通っても iPhone で落ちる可能性がある箇所です。

再読み込み → OKを押した**直後**に左下ボタンでOFF → そのまま一覧へ遷移するまで待つ →
一覧で左下ボタンをONにする。

- [ ] 蒼穹が**曲の頭から**鳴り始める

**鳴らない場合** → `play() → pause()` による解錠が iOS で維持されていないということ。
設計書 §5-2 のフォールバック（音量0のまま流し続け、到達時に巻き戻す）へ切り替える必要が
あるので報告してください。

### B-2c. アプリを切り替えて戻っても壊れないか

`fadeAudio` は `requestAnimationFrame` で動くため、タブが隠れている間は進みません。
また iOS は Safari が背面に回ると再生を止めます。

- [ ] 一覧への遷移が正常に完了する（心音が止まったまま固まらない）

## 既知の見送り事項

レビューで指摘されたが、今回は直さないと判断したものです。壊れているわけではなく、
「そういう仕様」として残っています。気になったら次の作業で扱えます。

- **左下ボタンのタップ領域は約31px四方**で、モバイルの推奨44pxを下回っています。2026-08-14 に「今回は触らない」と決めた項目です。押しにくいと感じたら拡大できます（透明な余白を外側に広げるだけで、見た目は1pxも変わりません）。
- **iPhoneではフェードと音量指定が効きません**（B-2a 参照）。Web Audio を持ち込めば直りますが、今回のスコープ外としました。
- **70秒のフェイルセーフが発動した場合、音ボタンが効かなくなります。** 何もかもが固まったときの最後の手段なので、そこに至った時点で既に異常な状態です。フェイルセーフは依存を最小に保つ価値のほうが大きいと判断して、そのままにしています。
- **扉の表示中に Tab キーで背後の音ボタンへ移動できます。** そこで Enter を押すと動画が一瞬止まりますが、OKを押せば復帰します。設計書の要求（フォーカス＋Enter/Space）は満たしています。
- **音をOFFにしても蒼穹は裏で進み続けます**（止めているのは音量だけ）。そのため再開位置は「消した地点」ではなく「その先」になります。ミュートボタンとしては自然な挙動なので、そのままにしています。A-5 の確認はこれで通ります。
