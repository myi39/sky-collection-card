# 音の扉（入口ポップアップ）設計書

作成日: 2026-08-14
対象: `sky_collection_card.html`
関連: `2026-08-12-loading-screen-design.md`（本書の §6 音の扱い・§7 BGMの変更 を一部上書きする）

## 目的

サイト訪問時に、音が流れることを伝える扉を1枚置く。扉のOKタップを**唯一のユーザー操作**として音の自動再生ロックを解き、ローディング画面の心音を1拍目から音付きで届ける。

## 背景 — 現状の3つの問題

### 1. 心音の演出が、ほぼ誰にも届いていない

音は初期OFF固定で（1377行目のコメントの通り、autoplay制限のため）、ONにする手段は左下の `♪ OFF` ピル1箇所だけ。`font-size: 10px` / `color: rgba(255,255,255,0.28)` の淡い小さなボタンにローディング中に気づいて押した人だけが心音を聴ける。

`movies/heartbeat_loop.mp4` はサイズの大半が音声で、`2026-08-12` の設計書はその音を前提に組まれている。演出の主要部分が構造的に届いていない状態にある。

### 2. 心音とBGMが被っている

```js
function handoffToBgm() {
  fadeAudio(loadingVideo, loadingVideo.volume, 0, 600);   // 心音アウト
  primeBgm();
  fadeAudio(bgm, 0, BGM_VOL, 1200);                       // 同時にBGMイン
}
```

両者を同時に走らせるクロスフェードのため、約600msのあいだ心音と蒼穹が重なる。

### 3. 蒼穹が頭から始まっていない

```js
function primeBgm() {
  if (bgmPrimed) return;
  bgmPrimed = true;
  bgm.volume = 0;
  bgm.play().catch(() => { bgmPrimed = false; });   // 再生したまま止めない
}
```

`primeBgm()` は音をONにした瞬間にBGMを音量0で再生し、**そのまま流し続ける**。ローディングは実効最短5秒・最長60秒あるため、本編に着いた時点で蒼穹はすでに数秒〜数十秒進んでいる。フェードインしても曲の途中から聞こえる。

## 決定事項

### 1. 画面フロー

```
ページ読込
  ↓  即座に表示（テキストのみ・待ち時間ゼロ）
┌─ #sound-gate (z-index: 700) ────────────┐
│   このサイトでは音が流れます                 │
│   音のオン／オフは左下でいつでも              │
│           [ OK ]                        │
└─────────────────────────────────────────┘
  ↑ この裏で心音動画を無音・不可視のまま先読み再生
  ↓  OK タップ（= 唯一のユーザー操作 = 音の解錠）
┌─ #loading-overlay (z-index: 500) ───────┐
│      心音（先頭から・音あり）                │
└─────────────────────────────────────────┘
  ↑ ここで初めて111枚の画像読込を開始
  ↓  拍のピークで
┌─ 画像一覧 ───────────────────────────────┐
│   （400msの静けさ）→ 蒼穹が頭から始まる       │
└─────────────────────────────────────────┘
```

扉とローディングは**別々の画面**とする。扉では心音を見せず、OKで暗転を挟んでから映像と音が同時に立ち上がる。心音の登場に最大の衝撃を持たせるための構成。

### 2. 扉は毎回出す（記憶しない）

localStorage 等で選択を記憶し、再訪時に扉をスキップする案は**採らない**。

扉をスキップすると音を解錠するユーザー操作が存在しなくなり、「音が流れます」と宣言しておきながら鳴らせない状態になる。ブラウザの自動再生ポリシー上、ページ読み込みごとにユーザー操作が必要なため、技術的に選択の余地がない。

### 3. ボタンはOK 1つのみ・デフォルトON

扉で押せるのはOKだけとする。音のオン／オフを扉で選ばせる2択案、およびOKの隣にトグルを置く案は検討したうえで採らない。全員に演出を届けること、入口で迷わせないことを優先する。

音を消したい人は、扉を抜けた直後から左下のボタンで消せる。その導線を本文で明示する。

**トレードオフの記録**: 公共の場で開いた人は、一度音を出してから左下のボタンを探すことになる。心音は `HEART_VOL = 1.0`（最大）で入るため、後述の800msフェードインを必ず維持すること。

### 4. コピーとビジュアル

```
┌──────────────────────────────┐
│                              │
│                              │
│     このサイトでは音が流れます    │   ← 15px / rgba(255,255,255,0.75)
│                              │
│    音のオン／オフは左下でいつでも  │   ← 11px / rgba(255,255,255,0.32)
│                              │
│          ┌──────────┐        │
│          │    OK    │        │
│          └──────────┘        │
│                              │
└──────────────────────────────┘
```

- 背景 `#080810`（`#loading-overlay` と同一）。継ぎ目を作らない
- 主文で事実を先に伝え、操作の説明は一回り小さく淡く下に置く
- **フォントはシステムUI**（`-apple-system, "Hiragino Sans", "Noto Sans JP", sans-serif`）。`letter-spacing: 0.08em`

  Papyrus は日本語グリフを持たないため、扉に指定しても効かずフォールバックする。既存の `.info-name` / `.info-desc` は英語サンプルのため気づかないが同じ状態にある。扉は日本語一択なので、フォールバック任せにせず明示的に指定する。ボタンの「OK」はラテン文字だが、本文と揃えるため同じシステムUIフォントとする
- OKボタンは `.bgm-btn` と同じ質感（`background: rgba(255,255,255,0.05)` / `border: 0.5px solid rgba(255,255,255,0.12)`）を一回り大きくしたもの
- OK後 400ms でフェードアウトし、DOMから除去する

### 5. 音の設計

#### 5-1. 扉の裏（OK前）

心音動画は現状のまま `autoplay muted` で再生させる。扉が不透明なため映像は見えないが、**動画のバッファリングが扉の滞在時間に吸収される**ぶん、ローディングの体感が現状より短くなる。

`loadingScreenReady()` も従来通りページ読込時から走らせ、扉のOKと `Promise.all` で待ち合わせる。扉に数秒滞在した場合、動画の準備は完了済みになる。

#### 5-2. OKタップの瞬間（すべてこのジェスチャーの中で同期的に実行する）

| 対象 | 処理 | 狙い |
|---|---|---|
| 心音 | `currentTime = 0` → `muted = false` → `play()` | 先頭の拍から、音付きで立ち上げ直す |
| 心音の音量 | `fadeAudio(loadingVideo, 0, HEART_VOL, 800)` | 既存の「いきなり最大音量にしない」方針を踏襲 |
| BGM | `play()` → 即 `pause()` | **鳴らさずに解錠だけする** |
| `soundOn` | `true` | 左下ボタンの初期状態をONにする |

`play()` をユーザー操作の中で明示的に呼ぶ形になるため、**iOS低電力モードで再生ボタンが描画される問題が構造的に解消する**（低電力モードが止めるのは自動再生であり、ユーザー操作起点の再生は通る）。ただし `#loading-still` と `.playing` クラスによる静止画フォールバックは保険としてそのまま残す。

`bgm.play()` は Promise を返し、直後に `pause()` を呼ぶと AbortError が出る環境がある。`.then(() => bgm.pause()).catch(() => {})` で握り潰す。

**要実機検証**: 「`play()` 直後に `pause()` しても解錠状態が維持される」ことは広く使われる手法だが、本プロジェクトはiOSで想定外の挙動を繰り返し踏んでいる。維持されない端末が見つかった場合のフォールバックは、**従来通り音量0で再生し続け、本編到達時に `currentTime = 0` に巻き戻してからフェードインする**方式（曲の頭出しという目的だけは達成できる）。

#### 5-3. 心音 → 音楽の受け渡し

```
拍のピークで revealSite() が呼ばれる
  0ms     心音 1.0 ──フェード600ms──▶ 0
  600ms   心音が無音に達する
          ───── 完全な静けさ 400ms ─────   ← 新設
  700ms     この間に loadingVideo.pause() / オーバーレイ除去（既存の挙動を維持）
 1000ms   bgm.currentTime = 0 → play() ──フェード1200ms──▶ 0.28
```

クロスフェードを廃止し、**心音が完全に終わってから音楽を始める**。`revealSite()` は拍のピークで呼ばれるため、「ドクン」の頂点で一覧が現れ、心音が引き、静けさがあって、蒼穹が入る。

定数として `BGM_START_DELAY_MS = 1000`（`revealSite()` 起点）を置く。

#### 5-4. 蒼穹は「初めて鳴らすとき」に必ず頭から

`bgmStarted` フラグを設ける。音が実際に聞こえる形で初めて再生されるとき（上記 5-3、または扉で音を消していた人が一覧で左下からONにしたとき）に `currentTime = 0` を実行する。

2回目以降のオン／オフは巻き戻さず、止まった位置から再開する（曲の途中で消してまた点けたときに頭に戻るのは不自然なため）。

### 6. 読み込みの順序とタイムアウトの起点

画像111枚の読込開始は**従来通りローディング画面が出てから**とする。扉の裏では心音動画のみを取りに行く。「111件の画像リクエストが動画を後回しにし、遅い回線でローディング画面が30秒出てこない（実測: 動画38.39s / 静止画32.42s）」という既存の設計判断（1501行目のコメント）をそのまま守る。

`init()` / `showCardButtons()` の呼び出し位置も変えない（扉とローディング資産の両方が揃ってから）。

**タイムアウトの起点をOK後に移す**:

| 対象 | 変更前の起点 | 変更後の起点 |
|---|---|---|
| `LOADING_MAX_MS`（60秒） | ページ読込 | OKタップ |
| 最終フェイルセーフ（70秒） | ページ読込 | OKタップ |
| `LOADING_ASSET_WAIT_MS`（2秒） | ページ読込 | ページ読込（変更なし） |

現状のままだと、扉を開いたまま放置した人の裏で本編が現れ、扉を閉じたら既に一覧が表示されている、という壊れ方をする。

`LOADING_ASSET_WAIT_MS` だけは動画の先読みを扉の滞在時間に吸収させる目的があるため、ページ読込起点のままとする。

### 7. 左下ボタンのアイコン化

`♪ ON` / `♪ OFF` のテキストを Lucide のSVGに置き換える。

| 状態 | アイコン | `aria-label` |
|---|---|---|
| 音あり | `volume-2` | 音を消す |
| 音なし | `volume-off` | 音を出す |

- **CDNは使わず、2つのSVGを直接HTMLに埋め込む**。追加リクエストが発生せず、`stroke="currentColor"` により既存の `color: rgba(255,255,255,0.28)` / hover `0.55` がそのまま効く。three.js のように実行時に必要なライブラリではなく、パス2本分の静的データにすぎない
- 両アイコンは同一形状のスピーカー＋波紋で、`volume-off` は波紋を斜線に置き換えた対になっている（`lucide-icons/lucide` の `icons/volume-2.svg` / `icons/volume-off.svg` で確認済み）。トグルしても形が破綻しない
- **表示するのは現在の状態**であり、押した後の結果ではない。`aria-label` のみ動作を書く
- アイコンサイズ 16px。pill形状（`border-radius: 16px`）・背景・枠線・hover は現状維持
- **タップ領域は今回変更しない**。現在の実効サイズは約20px四方で、モバイルの推奨44pxを下回っているが、今回のスコープ外とする（判断: 2026-08-14）
- 扉の上には表示しない（z順で扉が上）。ローディング中に前面へ出す `.bgm-btn.over-loading`（z-index 600）は維持する

### 9. エッジケース

- **キーボード**: 扉を開いた時点でOKにフォーカスを当てる。Enter / Space で発火（`<button>` の既定動作）。フォーカスリングを可視にする
- **Escape**: 割り当てない。扉を抜ける手段はOKのみ
- **スクロール**: 扉の表示中は背後をスクロールさせない
- **OK直後にOFFにした人**: ローディング中に左下でOFF → `revealSite()` の `if (soundOn)` が false になり音楽は始まらない。その後一覧でONにしたとき、5-4 の通り蒼穹が頭から鳴る
- **iOSのサイレントスイッチ**: `<video>` の音声はOSレベルで抑制される。従来通り、こちらでは何もしない

## 検証

自動テストの対象になりにくい領域のため、`serve` スキル経由の実機確認を主とする。

### 端末

iOS Safari（通常 / **低電力モード**）、Android Chrome、PC Chrome

### 確認項目

1. **iOS低電力モードで再生ボタンが出ないこと**（直近2コミットで対処していた問題。本設計で構造的に解消するはずの箇所）
2. OK直後、心音が先頭の拍から音付きで立ち上がること。音量がいきなり最大にならないこと
3. **心音と蒼穹が重ならないこと。蒼穹が曲の頭から始まること**
4. 扉のOK → ローディング中に左下でOFF → 一覧で再度ON にしたとき、蒼穹が頭から鳴ること（解錠が維持されていること）
5. 一覧で ON / OFF を繰り返したとき、2回目以降は曲が頭に戻らないこと
6. 扉を開いたまま2分以上放置し、その後OKを押しても正常にローディングへ進むこと（タイムアウト起点の移設が効いていること）
7. 左下アイコンが現在の状態（`volume-2` = 鳴っている）を表していること
